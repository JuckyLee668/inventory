# 基于 Electron 框架的库存管理 App 需求文档

## 1. 项目概述

### 1.1 项目背景
面向仓储与供应链场景，建设一套可离线运行、可联网同步、支持扫码与语音录入的桌面库存管理系统，提升出入库效率、减少人工录入错误、增强库存透明度。

### 1.2 项目目标
- 构建基于 Electron 的跨平台桌面应用（Windows/macOS/Linux）。
- 覆盖商品入库、出库、调拨、盘点等核心仓储流程。
- 集成条形码拍照识别与语音输入识别能力。
- 提供数据模拟存储与模拟上传机制，支持弱网与离线场景。
- 通过权限与审计能力保障业务安全合规。

### 1.3 项目范围
**包含：**
- 主业务模块：基础资料、入库管理、出库管理、库存管理、盘点管理、报表分析、系统管理。
- 智能能力：条码识别、语音识别、预警通知。
- 系统能力：RBAC 权限、操作日志、数据导入导出、移动端协同、可视化监控。

**不包含（本期）：**
- 实际财务总账系统对接（仅预留接口）。
- 复杂税务申报流程（仅提供简易核算字段）。

## 2. 用户角色与使用场景

### 2.1 角色定义
- **系统管理员**：用户/角色/权限配置、系统参数维护、备份恢复。
- **仓库主管**：审核出入库单据、调拨审批、库存监控、报表查看。
- **仓库操作员**：执行收货、验收、上架、拣货、复核、盘点。
- **采购/销售人员**：创建采购入库单、销售出库单、查询订单状态。
- **审计/管理层**：查看统计报表、绩效报表、操作留痕。

### 2.2 典型场景
- 到货通知后快速完成收货、验收和上架。
- 销售订单触发出库流程，完成拣货、复核、发运。
- 通过扫码枪/摄像头快速录入商品条码。
- 通过语音录入商品信息并结构化提取关键字段。
- 离线状态下完成操作，联网后自动同步数据。

## 3. 业务流程分析

### 3.1 入库流程
1. 到货通知与信息接收。
2. 货位规划、人员与设施准备。
3. 货物接收与单据核对。
4. 实物验收（数量验收、质量验收）。
5. 验收结果记录与异常处理。
6. 系统登记与上架管理。
7. 单据归档、数据统计与报表生成。

### 3.2 出库流程
1. 出库申请创建。
2. 审核确认。
3. 拣货作业。
4. 备货整理。
5. 出库复核。
6. 装车发运与发运记录。
7. 单据更新与归档。

### 3.3 特殊流程
- **调拨流程**：仓库间库存转移，含调出/调入双向确认。
- **报损/盘亏出库**：异常库存处理，需强制审批与原因记录。
- **换购出库**：按业务规则处理商品替换和库存扣减。

### 3.4 智能录入流程
- **条码识别流程**：图像采集 → 图像预处理 → 条码定位 → 解码识别 → 结果确认/重试。
- **语音录入流程**：语音输入 → 实时转写 → 热词匹配 → 结构化提取 → 用户确认 → 存储。

## 4. 功能需求

### 4.1 基础资料管理
- 商品信息管理（SKU、名称、规格、条码、单位、有效期策略）。
- 物料信息、设备信息管理。
- 供应商档案、客户档案管理。
- 仓库与库位管理。
- 自定义属性与字段配置。

### 4.2 入库管理
- 支持采购入库、退货入库、调拨入库。
- 支持到货通知、验收登记、上架任务。
- 支持按批次/序列号入库。
- 入库异常登记（短少、破损、错货）与处理闭环。

### 4.3 出库管理
- 支持销售出库、调拨出库、报损出库。
- 支持申请、审核、拣货、复核、发运全流程。
- 出库单据与凭证归档。
- 特殊场景支持：盘亏、换购。

### 4.4 库存管理
- 实时库存查询（商品/仓库/批次/状态多维度）。
- 安全库存阈值配置与低库存预警。
- 保质期预警（临期/过期提醒）。
- 批次与序列号追溯。
- 动态组合查询与可视化看板。

### 4.5 盘点管理
- 周期盘点、临时盘点。
- 盘点任务分派与执行跟踪。
- 盘盈盘亏处理与审批。
- 盘点报表输出。

### 4.6 订单与协同管理
- 订单创建、跟踪、历史记录。
- 自动分配任务与操作指引推送。
- 团队协作与按仓库/渠道/订单类型的数据权限细分。

### 4.7 条码识别模块
- 支持 EAN-13、Code 128、QR Code。
- 支持摄像头拍照识别与外接扫码设备。
- 采用 ZXing 等开源库进行解码。
- 识别错误处理：图像质量优化、多格式策略、扫描区域优化、硬件兼容处理。

**指标要求：**
- 首读率 ≥ 98%。
- 误码率 ≤ 1/1,000,000。

### 4.8 语音识别模块
- 采用 faster-whisper 模型（建议中型模型）。
- 支持中文普通话及常见方言口音。
- 支持商品名称热词注入。
- 生产日期、保质期支持 OCR+NLP 联合解析。

**指标要求：**
- WER ≤ 5%。
- 首读率 ≥ 98%。
- 响应时间 ≤ 4 秒。
- STOI ≥ 0.8，PESQ ≥ 4.0，MOS ≥ 4.2。

### 4.9 数据上传与同步模块（模拟）
- 前端通过 HTTP POST + JSON 提交数据。
- 后端模拟写入 SQL（INSERT 或 ORM）。
- 大文件支持分片上传、断点续传、完整性校验。
- 弱网与异常场景支持指数退避重试。
- 支持实时同步（秒级）与离线同步（T+1 批量）。
- 冲突检测与解决（幂等键、版本号/乐观锁）。

### 4.10 报表与分析
- 库存报表、出入库统计、分析图表。
- 自动化报表定时推送。
- 员工绩效报表。
- 导出格式：Excel、PDF、CSV。

### 4.11 系统管理与安全
- 用户管理、角色管理、权限管理（RBAC）。
- 系统配置、参数设置、备份恢复。
- 通知提醒（库存预警、保质期提醒、任务通知）。
- 操作日志、审计追踪。

### 4.12 扩展能力
- 多语言支持。
- 移动端支持（手机/平板）。
- 云服务与多端同步。
- 智能硬件集成（PDA、RFID、扫码枪）。
- 视频监控集成（可选）。

## 5. 非功能需求

### 5.1 性能需求
- 关键业务操作响应时间 ≤ 1 秒（查询、单据提交、状态刷新）。
- 语音识别请求端到端响应时间 ≤ 4 秒。
- 应用冷启动时间满足桌面业务可接受范围（建议 ≤ 3 秒）。

### 5.2 安全需求
- 账号认证与细粒度授权（RBAC）。
- 敏感数据加密存储与传输加密。
- 符合 ISO27001 管理要求。
- 满足等保三级相关管控要求（按部署环境落实）。
- 遵循数据安全法及企业数据分级制度。

### 5.3 可靠性与可用性
- 异常网络场景可自动重试与恢复。
- 关键数据写入需具备事务一致性或幂等保障。
- 应用崩溃恢复后可继续未完成任务（断点续传/草稿恢复）。

### 5.4 易用性
- 常用操作路径不超过 3 次点击完成。
- 支持扫码与语音两种快速录入方式。
- 提供清晰的异常提示与纠错建议。

### 5.5 可扩展性与可维护性
- 模块化架构，支持插件式扩展（识别引擎、报表模板、硬件驱动）。
- 统一日志与监控埋点，便于问题定位。

## 6. 系统架构设计

### 6.1 Electron 技术架构
- **主进程**：窗口生命周期、系统资源管理、原生 API 调用。
- **渲染进程**：业务界面与交互逻辑。
- **Preload 层**：受控 API 暴露，启用上下文隔离。
- **IPC 通信**：主渲染进程数据交互与事件分发。

### 6.2 分层建议
- 表现层（UI/页面/组件）
- 应用层（用例编排、状态管理）
- 领域层（库存、单据、规则）
- 基础设施层（本地存储、网络、识别引擎、日志）

### 6.3 技术选型建议
- 前端：Electron + React/Vue（任选其一）
- 状态管理：Redux/Pinia
- 本地存储：SQLite（本地）+ 可选 MySQL（中心库）
- 条码识别：ZXing
- 语音识别：faster-whisper

## 7. 数据库设计（示意）

### 7.1 核心实体
- 商品（product）
- 库存（inventory）
- 仓库（warehouse）
- 库位（location）
- 入库单（inbound_order）
- 出库单（outbound_order）
- 盘点单（stocktake_order）
- 调拨单（transfer_order）
- 用户（user）
- 角色（role）
- 权限（permission）
- 操作日志（operation_log）

### 7.2 关键关系
- 商品 1:N 库存记录
- 仓库 1:N 库位
- 入/出库单 1:N 明细行
- 用户 N:M 角色，角色 N:M 权限

### 7.3 模拟数据填充
- 提供 MySQL 存储过程进行批量模拟数据生成。
- 支持测试环境按场景注入（高并发入库、弱网同步冲突等）。

## 8. 接口与集成要求（示意）

### 8.1 数据提交接口
- `POST /api/inventory/events`
- 请求体：JSON（事件类型、业务单号、时间戳、操作者、明细）
- 返回：处理状态、幂等键、失败原因

### 8.2 分片上传接口
- `POST /api/upload/chunk`
- `POST /api/upload/complete`
- 支持断点续传与完整性校验（MD5/SHA-256）

### 8.3 冲突处理接口
- `POST /api/sync/conflict/resolve`
- 策略：最后写入优先、版本优先、人工确认（按业务配置）

## 10. 验收标准

### 10.1 功能验收
- 入库、出库、盘点、调拨全流程可闭环执行。
- 条码识别、语音录入达到既定准确率指标。
- 报表导入导出与权限控制满足业务要求。

### 10.2 非功能验收
- 关键操作性能符合 ≤1 秒目标。
- 异常网络下数据不丢失，可自动重试恢复。
- 安全基线检查通过（鉴权、加密、审计）。
